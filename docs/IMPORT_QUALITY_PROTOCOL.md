# 导入质量评测规则

本规则落实 [vNext M0](NEXT_MAJOR_VERSION_PLAN.md#3-第一阶段不同模板简历导入识别检查)。执行进度和结果入口只维护于 [plan.md](../plan.md)。规则版本由 `fixtures/import-quality/corpus.mjs` 的 `policy.version` 标识。

`fixtures/import-quality/corpus.mjs` 保存 72 份有效样本和 12 份边界场景的匿名清单、独立答案、模板家族、分组、语言、预期页码与预先声明支持等级。答案来自人工编写的合成内容，不调用解析器或模型生成答案。禁止根据识别结果回写答案。

开发组 60 份，外部保留组 12 份；模板家族不跨组。开发组中六份内置模板须使用真正的冻结导出，不用仿制 PDF 代替。生成器未覆盖的场景明确标 `pending`，不算成功、拒绝或有效输入；仅有清单不代表已经制备或验证了 84 份样本。外部在此指非 ZineCV 版式的合法合成资料，仍须检查几何与复杂度是否足以代表声明家族，不宣称它们是第三方真实简历。

外部生成路径为 Chromium 打印、Canvas/JPEG PDF、OOXML 包、SVG/Canvas 栅格图。原始字节与大图不进受控目录，保留生成规则及输入 SHA256。报告记录生成器、评分器与产品输入文件哈希；Chromium/字体更新可能改变字节，需要在同环境复测，不对生成文件作永久字节冻结。

policy 3 变更：字符准确率改为空白不敏感（预先声明的折行规范化——物理折行不插入源文字符，数字、标点与正文顺序仍计差；字段等值与段落对应保留行结构规范化）。版式家族从 16 个扩展到 22 个：悬挂标签、交叉栏、仪表盘、栅格账本的失败曾用于修复，已按协议转入开发组槽位；保留组改由六个全新几何承担（html-banner、html-right-rail、html-footer-nav、raster-banner、raster-two-band、raster-right-rail），旋转与低对比变体保留在开发组槽位。提取层的栏间隙检测、OCR 词级分段、栏序（含顶行所在栏在先）与章节标题前缀识别按这些家族的几何证据实现，判据都在 `pdf-reading-order.ts` 与 `resume-content-recognition.ts` 内有注释说明。

policy 4 仅扩充独立验收覆盖，不改评分阈值或原答案：原48份（包括前轮保留组10份成功与2份失败）全部转开发回归，保留其原制作规则和真值。新增 IQ-49..60 由未读取产品识别代码和报告的独立上下文设计，冻结为 `blind-holdout-policy4.json`，SHA256 `e3e24c8ffb155c1c756edb09052a4760a97f45efc3b068f90900ffb0c78b56e2`。六个新几何分别是工作条目双卡片、记录矩阵、层级缩进、横向记录、跨页变栏及工作拼贴，中英文各一份，均预声明内容与结构支持。先验核对渲染与坐标，再运行识别；不得根据识别结果修改答案或版式。原policy 3失败报告继续保留，不被新报告覆盖。

policy 5 再扩充六个独立几何，不改前60份答案、制作规则和支持等级。policy 4整组已转开发回归，原失败报告保留；新增 IQ-61..72 冻结于 `blind-holdout-policy5.json`，SHA256 `916e4810f8221af4a184f7c8a93fdd63c57f17447249c66b0cf4ac11cf20ff29`。包括跨页条目、资历与工作分章、页脚联系区、跨栏教育、反L工作区及同文档竖横页；全部在识别前完成逐页渲染、物理尺寸和目视核对。独立设计者完成冻结前未接触产品代码或识别结果；冻结后参与开发诊断不改已冻结输入。规则仍要求每份达标，不能用平均分抵消失败。

字符指标用 Unicode NFC、CRLF 统一与逐行水平空白规范化后的 code point 编辑距离；不删除数字、标点，不排序正文，不把字符集合保留率当准确率。最短编辑对齐将每个标准段单调对应到实际识别 span：段必须非空、局部相似度至少 0.60、不能更像另一标准段、不能超出标准允许的重复次数。0.60 仅用于建立对应，不替代全文 99%/95% 门槛；缺失、换序、重复、无法对应均不能通过。唯一完整段落锚点分块，重复锚点不猜；大块使用 Hirschberg 线性空间精确对齐，每个追溯矩阵不超过4,000,000格，两行cost向量总长度超该上界则明确记未解决，不扩大内存预算。物理换行仍按声明的字符规则计差，不用对齐消除误差。正文目标 `destinations` 精确保留实际识别 span，不能在映射成可编辑字段时二次丢字；允许普通 OCR 误字在全文门槛内原样保留。字段按路径和值配对；错误与额外非空语义字段计入 precision 分母，缺失计入 recall。关键字段精确率、覆盖率单列，条目数量及模块顺序另列。正文保留不代表可编辑结构已通过，原文必须能追溯到最终字段或待核内容。

冻结目标沿用计划：清晰文字每份 ≥99%，OCR 每份 ≥95%，声明支持类别字段 F1 ≥95%；可靠关键字段全部精确，安全项全部通过。困难类别预先标明降级范围，但基线失败仍逐份展示，不在结果出来后移出分母。报告 `需校正` 不能当作阶段验收通过。

运行清单检查：`node tools/import-quality-baseline.mjs --check`。

运行开发基线：`node tools/import-quality-baseline.mjs`。定向诊断用 `--id IQ-31,IQ-44`；基线允许记录失败并正常退出，强制验收须显式加 `--gate`。保留组仅在修复完成后用 `--holdout --gate`；被用于修复的家族须转开发并补入全新家族，更新规则版本和清单。

内置对照使用 `node tools/generate-import-builtin.mjs` 由归档 alpha.2 真实引擎生成，校验发布 EXE、构建收据与 PDF 回执，在独立 profile 工作并清理。它是历史发布引擎的输入生成证据，不代表当前宿主资格。每个模板覆盖短内容与 32 段匿名长内容；实际页数取生成回执；六份现有内置来源已用 Poppler 渲染逐页独立核对，标注保存在 `builtin-page-annotations.mjs`。标注只对应已审阅 PDF 的摘要，字节或阅读单元数量变化时返回未知，重新标注即可，不冻结未来输入。合法加密输入由 `fixtures/import-quality/encrypt-pdf.py` 使用开发环境的 pypdf 生成并自行验证密码；通过 `ZINECV_PDF_PYTHON` 指定 Python，无需产品新增依赖。

内置样本的语义seed与显示原文答案分开：`builtin-source-answers.mjs` 依据已核发布源码规则独立标注联系方式合行、URL显示标签、中文日期、默认学历方式及明确装饰glyph，映射回原seed正文目标；不读取 PDF 解析结果或 TextMap 生成答案。报告另存显示答案及规则证据摘要；六份内置对照的具体页码及跨页段落已独立标注；跨页段落同时保留全部页码，段落主页只记起始页。未在这些输入出现的跨页继续标题不推定为已核对，不能全局删除重复标题或私用区字符来提分。

现版对照可用 `--reference a1ce113445fb1bfd7216b4dd6f244e19d96a7c3d`：私有 Vite server 从 Git 对象读取列出的原版识别服务，不还原或覆盖工作树；样本与独立评分规则保持当前版本，报告分开记录产品引用提交及各服务摘要。此模式只证明相同依赖下这些识别入口的差异，不能当原发布安装包全链复测。

## 操作场景执行方法

开发基线的四个操作边界按真实操作执行，不以文件拒绝冒充，也不放宽任何阈值（120 秒超时、单解析任务并发限额保持原值并在执行时断言）。执行方法与判定依据随报告写入每个边界的 `method`、`evidence` 与 `scope` 字段。

- IQ-B09 超时：基线在专用浏览器页面上先安装 Playwright 虚拟时钟（`page.clock.install()`），再加载生产 `recognizeTemplate` 并用真实扫描图片进入 OCR；观察到"正在加载中英文 OCR 模型/正在识别"进度后 `fastForward(120000)` 推进虚拟时间，使产品内部 `IMPORT_LIMITS.timeoutMs` 计时器真实触发。判定依据：识别以 `AbortError`/"导入超过两分钟限额"失败——该消息只能由内部计时器分支抛出；同一页面随后对合法文本 PDF 的识别成功，证明并发名额已释放。报告记录虚拟推进量、推进前后真实耗时与进度日志。
- IQ-B10 取消：OCR 进行中（进度出现"正在识别文字"）在进度回调内同步 abort。判定依据：识别以 `AbortError`/"导入已取消"失败，且 abort 命中点确在 OCR 阶段（以错误消息区别于内部 120 秒计时器路径）；同一页面随后一次合法识别产出完整模板（extractedText、resume、预览 data URL），证明并发名额与 OCR 会话已随 abort 释放——并发闸为 1，名额未释放则该次必然被并发闸拒绝。
- IQ-B11 重试：同一页面连续两次用截断 PDF 触发解析失败（失败发生在名额占用之后），判定依据：两次都得到非 AbortError、非并发闸的解析错误；随后合法输入成功，证明每次失败都经 finally 释放名额，`activeRecognitions` 不泄漏。
- IQ-B12 目标切换：浏览器页面无法注入 IPC mock，不做端到端宣称。基线以 `node --test --test-name-pattern IQ-B12 tests/unit/import-safety-operations.test.mjs` 取证；该测试加载生产确认路径（`runApplyImportDraft`）与 mock 原生客户端，断言目标切换后确认在原生写入前被拒绝、flush 复检拒绝、回执属于已切换编辑来源时拒绝采纳、结果在采纳前过期不进入编辑器，且目标未切换时确认仍写向捕获的 cursor。报告字段 `scope: "unit-evidence"`，附测试输出尾部与退出码。

操作场景条目的 `passed` 由各自操作断言决定，不再使用 `Boolean(observed.error)`；文件拒绝类边界（B01–B08）判定不变。

输出默认在 `.artifacts/import-quality/development/report.json`，使用 `--output` 为现版基线、定向回归、验收结果分配独立目录，避免覆盖旧证据。未知/空选择和错误组 ID 拒绝运行；局部 `--gate` 只标局部门禁，`--gate --check` 互斥。`inputsStable` 仅证明报告列出的来源/夹具文件前后稳定，不代替依赖、字体与全部资源的冻结构建收据。报告记录候选、原文、provenance、警告、耗时与采样 JavaScript 堆；JS 堆不包括 OCR worker、WASM 和原生进程，不能当作总峰值资源。可加 `--measure-memory` 调用 Windows 真实采样器，记录当前评测所属的 Node/Chromium/OCR/Python/PowerShell 进程树、私有内存与工作集、实际最大采样间隔和退出状态，原始样本写 `process-memory.json`。这包含生成器、测试框架和采样器开销，是采样峰值，不等同于安装态原生宿主峰值，也不把缺失采样记为零。人工校正时间与本评测的安装环境闭环保持未测；四个操作边界（超时、取消、重试、目标切换）按「操作场景执行方法」在开发基线中实际执行，其证据不构成阶段验收。最终出口还要求真实总资源测量、来源核对、安全应用及导入到重启导出的完整链。
