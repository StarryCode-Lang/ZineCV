## 2. 环境与构建（必读）

- Windows + MSVC；**所有 cargo/clippy/test 必须经 `tools/with-msvc.ps1`**（直接 cargo 会在链接阶段因 MSVC 环境缺失失败）。npm 脚本已封装（`npm run check:native` 等）。
- Node ≥ 24；`npm ci` 安装依赖；Rust toolchain ≥ 1.88（rust-version）。
- Cargo 单套输出 `src-tauri/target`（dev/release/hooks 三 profile 共用一个 target 根）。首跑全量重编译约 10–20 分钟。
- 开发只用 `npm run dev`（自动准备 MSVC 并启动 Tauri 桌面端）；发布只用 `npm run package:windows`，生成 NSIS 安装器 `.exe`（WebView2 在线引导安装，包更小）。`src-tauri/target/release/zinecv-desktop.exe` 是构建中间产物，不作为独立安装包交付。离线安装器需内嵌 WebView2 运行时，会明显增大体积，不作为默认交付。
- `npm run package:windows` 内部执行 Vite 构建、Rust release 编译和 NSIS 打包；前端 `dist/` 与 Cargo `target/` 都是构建输出。验证流水线仍通过 `npm run build:native` 生成原生宿主。
- 干净克隆复现细节曾记录于 docs/clean-clone-repro-20261002.md（已并入本文件 §9）。
- `.gitignore`：node_modules/、dist/、src-tauri/target/、.artifacts/ 均不入库。

### 15.3 改动清单（全部零功能损失）

1. **字体单一来源**：`engine.rs` 的三份字体常量改为 `pub(crate) static`，`storage/resources.rs` 不再各自 `include_bytes!` 同一份文件。逐字节探针实测：改动前每份字体在 exe 中出现 **2 次**，改动后 **1 次**。
   - 顺带修掉一个真实缺陷：`const` + `include_bytes!` 会在每个代码生成单元各展开一次，debug 构建实测每份字体 **3 份**；改 `static` 后 debug 测试二进制减少 46.7 MB。该缺陷在 release（fat LTO、单 CGU）下不可见，只在 debug 暴露。
   - 字体字节与拼接顺序未变，`fontBundleHash` 与既有模板修订的资源身份保持稳定。
2. **零拷贝字体字节**：`RenderFontBytes` 由 `Vec<u8>` 改为 `typst::foundations::Bytes`。`Bytes::new(&'static [u8])` 官方即支持「不额外分配」；此前 `RenderFontBytes::default()` 每次构造都复制约 22 MB，而一页求解最多构造 16 次。`parse_font_bundle` 改为共享同一缓冲。新增两个可证伪断言测试：`bundled_font_bytes_are_zero_copy_static_views`（指针等于静态量地址）、`bundled_font_materials_are_cached_not_recopied`（两次构造指针相同）。
3. **宿主资源材料缓存**：`host_resources()` 原本每次渲染都复制约 22 MB 字体重算一次 SHA-256；改为进程内 `OnceLock` 缓存一份（材料以 `Bytes` 共享），每次渲染只克隆引用计数。
4. **Cargo 发布档**：新增 `[profile.release]`（`opt-level=3`、`lto="fat"`、`codegen-units=1`、`panic="abort"`、`strip="symbols"`）。此前**完全没有** `[profile.release]` 段，即 rustc 默认（无 LTO、16 CGU、unwind、不 strip）。`[profile.hooks]` 保留 `inherits="release"` 但用 `lto="thin"` 以缩短测试构建（该档只用于故障注入验证，不是发布产物）。
   - `panic="abort"` 是**语义变更**而非纯体积选项；其不回归由 WebView2 故障套件实测覆盖（见 15.5）。
5. **删除已证明永不被请求的前端资源**：`public/ocr/tesseract-core-lstm.wasm`（2,855,361 B）。证据链：`template-import.ts:23` 把 `corePath` 设为 `.../tesseract-core-lstm.wasm.js`；tesseract.js `worker-script/browser/getCore.js:21-22` 规定 `corePath` 以 `js` 结尾时逐字 `importScripts`，SIMD 探测分支不可达；且该 `.js` 内联的 base64 段解码后与被删文件逐字节相同。删除后 `docs/resource-license-inventory-20260930.json` 已重新生成（`--check` 回到 0）。
