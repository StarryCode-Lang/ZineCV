# 下一个版本开发大计划

2026-10-28 · 规划稿 · 工作代号 vNext

下一大版本的主线：**可靠导入 → 多份简历管理 → 岗位定制 → 投递前检查**。

当前版本按用户确认视为功能开发完成。唯一结转需求“检查导入不同模板的简历，确认项目能否成功识别”，正式纳入下一版本第一阶段。先建立识别质量基线，再根据结果改进，不重新启动已经完成的功能开发。

本文规定范围、顺序和验收方法，实际执行进度只维护在 [plan.md](../plan.md)。本计划已交付并进入执行，当前完成范围与剩余事项以 plan.md 为准。vNext 是开发周期名称，实际发布版本号在立项时确定，不因本次规划修改产品版本。

## 1. 版本目标

让用户可以把已有简历可靠地带进来，维护自己的多份简历，针对不同岗位形成可审阅的版本，并清楚知道导出的文件是否存在内容遗漏、结构错误或排版问题。

| 优先级 | 方向 | 应交付的结果 |
| --- | --- | --- |
| P0 | 不同模板导入识别评测 | 独立样本、标准答案、分项报告和明确支持范围 |
| P0 | 评测发现的问题修复 | 可复现、可回归；关键内容不静默遗漏，失败不污染原简历 |
| P1 | 导入核对体验 | 来源可追溯、待核字段可解释、未归类内容可校正 |
| P1 | 多份简历管理 | 创建、复制、命名、搜索、归档和切换，各自保存草稿与版本 |
| P1 | 岗位定制 | 岗位要求对应已有事实，复用分支和助手生成可确认的修改 |
| P1 | 投递前检查 | 内容与版面问题可定位，导出目标和冻结修订清楚 |
| P2 | 更多模板、素材复用与更广语言 | 主线完成后按需要选做，不成为启动前提 |

识别质量决定进入系统的数据是否可靠；多简历管理提供清楚的文档归属；岗位定制复用已有版本和助手；投递前检查完成交付闭环。优先完成这条流程，比同时增加多个平台或大量模板更容易产生可验证的用户价值。

本版保持 Windows、本地优先、匿名可编辑和现有 React/Tauri/Rust/Typst/SQLite 架构。云同步、多人协作、移动端、完整 OHOS 宿主、招聘网站自动投递、模板市场和任意外部模板的像素级复刻，列入后续候选。

| 领域 | 现有基础 | 下一版增量 |

| 版本 | 提交、分支、历史载入、比较、删除保护、备份恢复 | 独立简历入口与岗位关联，不另造版本系统 |
| 助手 | 显式引用、流式会话、受限工具、待审提议、拒绝与撤回、预算与迟到保护 | 岗位要求与简历事实的对应关系、可解释的定制建议 |
| 导出与交付 | 冻结输入的 PDF/PNG、原生保存、签名更新、安装与恢复路径 | 导出前报告、目标版本展示、新数据升级保留 |
| 跨平台 | Browser/WASM 有共享核心接线，OHOS 为核心适配 POC | 保持边界，不扩成新的平台交付承诺 |

**独立简历、来源上下文、分支/提交是三种不同身份。** 独立简历对应文档；来源上下文保存该文档在某个导入来源下的草稿；分支和提交记录版本。存储层已有文档 ID 与部分隔离能力，但桌面命令仍围绕 `DEFAULT_DOCUMENT_ID` 工作，多简历功能需要宿主、持久化和界面共同演进。

现有导入测试已经覆盖双栏 PDF、复杂 DOCX、扫描与取消。缺少的是跨来源、跨版式的独立质量基线，而不是 PDF/DOCX/OCR 功能本身。`output/pdf/` 中两份自家合成导出不能代替外部模板评测。

历史 pending、用户自行管理的人工体验和旧提速记录保留原含义，不因本计划恢复为本版未完成事项，也不改写成新的自动化通过。

## 3. 第一阶段：不同模板简历导入识别检查

### 3.1 怎样判断“成功识别”

四层分别验收，不能只看文件是否打开：

1. **读到内容**：应处理页面的正文被提取，文字层与 OCR 路径选择合理，没有静默漏页。
2. **理解结构**：基本信息、教育、工作、项目、技能、日期进入正确字段；经历不错误合并、拆分或串栏。
3. **能够核对**：候选能追溯到来源片段与已知页码，低置信项和未归类内容可见，用户可以校正。
4. **能够继续使用**：确认后可以编辑、保存、重启恢复和导出；失败、取消、过期确认不修改错误目标。

来源预览正常、抽到了文字、识别出多个章节或近似配色，都不能单独代表通过。内容导入后套用 ZineCV 模板，与精确复刻外部版式分别记录；本版主线保证内容与可编辑性，样式只在明确范围内近似。

### 3.2 首批样本矩阵

建议准备 **48 份有效样本 + 12 份边界/异常样本，共 60 份**。这是计划规模，不是已有材料数量。复用现有生成器与合法样本，不恢复已删除的历史运行目录。

| 有效样本组 | 数量 | 重点检查 |
| --- | ---: | --- |
| 内置三模板导出后再导入 | 6 | 当前闭环对照，覆盖模板、密度、长短内容 |
| 外部单栏文本 PDF | 6 | 中英文、混排、联系方式、链接、字体与断行 |
| 双栏/侧栏/跨栏标题 PDF | 6 | 栏内与栏间顺序、标题归属、重复与遗漏 |
| 三栏/图形化/复杂时间轴 PDF | 6 | 能力边界、内容保留与明确降级 |
| 纯扫描多页 PDF | 6 | 每页 OCR、页序、旋转、小字、低对比度 |
| 文字与扫描混合 PDF | 6 | 按页核查，不因少量可提取文字跳过扫描正文 |
| DOCX | 6 | 表格、列表、文本框、页眉脚、浮图、跨页经历 |
| 图片/截图/长图 | 6 | 中文小字、缩放、压缩、透明背景、旋转 |

外部样本至少覆盖 12 个独立模板家族和 4 种制作或导出来源。相同模板只换配色或正文，不算新的模板家族。使用自有、人工合成或明确许可资料，保留真实版式复杂度，避免真实个人信息进入公开夹具。

交叉覆盖中文、英文、中英混排，1 页、2 页和更长文档，以及无日期、时间重叠、同名机构、多段经历、长网址、特殊符号；不要求把全部维度做笛卡尔积。

12 份异常样本覆盖空/损坏文件、加密 PDF、扩展名与内容不符、ZIP 高压缩比、超体积、超页数、超像素、超时、取消、连续重试、解析期间切换目标。部分候选应用、重复确认和取消后恢复作为操作场景追加检查。

48 份有效样本中，36 份用于开发诊断，**12 份外部样本保留用于阶段验收**。同一模板家族及其变体不能同时进入两组；保留组不参与调参。自家模板仅作回归对照，不能填充外部保留组。某个保留样本一旦用于修复，就转为回归样本，并补入新的未见样本。

### 3.3 标准答案与记录

每份样本记录匿名 ID、格式、制作来源、模板家族、语言、页数、大小、输入哈希、许可、文字层类型和预期支持等级。标准答案标注完整正文顺序、模块/经历边界、字段值、日期、链接及来源页码；原文不存在的字段标为缺失，不凭常识补齐。

结果同时记录候选、来源、警告、未归类内容、耗时、峰值资源、需人工修正的字段和最终结论。评分使用独立标准答案，不能把解析器自己的输出当答案，也不使用同一模型同时生成和判定答案。

可生成样本优先保留规则；不可再生的合法外部样本只保留必要份数与标注。大截图、profile 和逐轮日志写入忽略目录，受控证据保留可追溯摘要及必要失败信息。

### 3.4 指标与建议门槛

先测现版，再在修复开始前冻结支持范围、分组和门槛。以下均为下一版目标，**不是当前实测准确率**。既有 golden 测试阈值、阅读顺序断言和安全预算不放宽。

| 指标 | 定义 | 建议目标 |
| --- | --- | --- |
| 正文字符准确率 | `1 - 编辑距离 / 标准字符数`，截断到 0–1；空文本单独判断 | 支持的清晰文本样本每份 ≥99%，清晰 OCR 样本每份 ≥95% |
| 字段映射 | 标准字段与值配对，分别报告 precision、recall、F1 | 每个声明支持的模板类别 F1 ≥95%，逐样本列出失败 |
| 关键字段 | 姓名、电话、邮箱、机构和日期分别精确比较 | 标为可靠的关键字段全部匹配，不能确认的明确待核 |
| 经历与阅读顺序 | 模块顺序、条目边界、条目归属和有序段落 | 支持样本无串栏、错误归属或未说明的合并/拆分 |
| 内容去向 | 每段属于已映射、待归类或明确告警 | 无静默漏页、漏段、重复经历；无法恢复的部分明确提示 |
| 安全应用 | 取消、失败、部分选择、重试、目标变化、重启 | 全部通过，不用平均成功率抵消数据错误 |
| 校正成本 | 修改字段/条目数量、完成核对时间 | 先建立基线，用相同任务对照，不预写未经测量的提速比例 |

字符比较只允许预先声明的 Unicode、换行等规范化，不能消除数字差异或正文顺序。字段指标同时展示分组结果和每份失败；关键字段另报覆盖率与待核率，不能靠把全部内容标成待核制造高准确率。

结果分类为“内容与结构通过”“需校正”“明确不支持/拒绝”“异常失败”。异常样本正确拒绝只算边界行为通过，不计正常识别成功率。困难样本可以明确不支持，但不能看到结果后悄悄移出分母或改标签。

### 3.5 优先验证的源码边界

以下是静态发现的风险点，先用样本复现，再决定修复；不提前宣布当前版本验收失败。

| 实现线索 | 首先验证 | 复现后的改进 |
| --- | --- | --- |
| PDF 在整份提取文本为空时才进入扫描 OCR | 文字首页+扫描后页、只有页眉含文字、部分页缺文字映射 | 按页判断文字覆盖，必要时逐页 OCR，合并来源与顺序 |
| 图片当前先缩至最多 560×760 | 中文小字、密集双栏、高清纵向长图 | 分离预览缩略图和 OCR 输入，在既有预算内选分辨率或分块 |
| high/medium/low 主要由章节数量决定 | 标题齐全但字段错误、正文完整却无标准标题 | 根据证据、冲突和覆盖解释待核原因，不把章节数当准确率 |
| 章节别名和日期模式承担主要结构识别 | 非标准标题、英文月份、无日期经历、机构/职位/城市同一行 | 针对失败增强分段与字段归属，未确定内容进入待归类区 |
| 外部样式映射到有限内置模板 | 复杂侧栏、图形化内容、跨页样式变化 | 清楚说明近似范围，优先保留内容，再完善样式映射 |

现有导入上限为 18 MiB、50 页、4000 万像素、120 秒及单解析任务。算法调整同时验证取消、任务释放和资源峰值，不通过扩大预算、删 OCR 或跳过困难页面过关。

### 3.6 修复闭环与出口

流程：**准备标准答案 → 现版基线 → 失败分类 → 最小复现 → 定向修复 → 同类及既有回归 → 保留组验收 → Windows 安装环境复核**。

错误分为读取/解码、OCR、阅读顺序、字段映射、样式近似、候选应用、资源/超时七类。先修静默丢内容、串字段和错误写入，再提高普通识别率与样式近似。没有复现证据的问题先记录，不扩成解析框架重写。

交付物只有三项：**样本与标注规则、分层识别报告、确认问题与回归结果**。报告写清每类支持范围、每份失败、旧基准是否退化及剩余待核项。若已经达到目标，只补评测与说明，不为升级强行更换解析器。

阶段出口：正常支持样本达到冻结门槛；困难样本有内容去向和降级说明；安全项全通过；完成“导入→核对→编辑→保存→重启→导出”。这一结果作为下一版扩展功能的入口。

## 4. 导入核对体验

复用已有候选审阅、来源证据和事务应用，形成一个清楚的核对过程：原始来源与结构化结果对照，先处理关键字段，再处理未归类内容，最后确认目标和变更范围。

必须交付：

- 每个候选可查看来源片段；已有页码/坐标时定位，没有时只展示真实可得信息。
- 分别说明识别不确定、字段缺失、多候选冲突和未归类内容，优先标出联系方式、日期与归属问题。
- 可以修正字段、调整模块归属、拆分或合并经历；保留未选择内容和提取原文用于核对。
- 应用前明确目标与改动，与已有内容冲突时选择替换或保留，不能静默覆盖。
- 取消、失败、重试和切换目标状态清楚，迟到结果不能应用到新的简历。

需要扩展校正契约时，由 Rust 定义允许修改的字段和目标，检查来源、白名单、cursor 与完整变更集合；不能把前端任意 JSON 直接写成可信文档，也不手改生成绑定。

多页来源按需加载，避免一次保留全部高清页面。继续保留 DOCX 受限预览和外部资源限制。离线识别为默认；云端补充识别须另行设计发送范围及用户选择。

验收：能从错误候选定位来源并校正；未选字段不写入；重复确认幂等；过期目标拒绝；校正内容在重启和导出中一致。

## 5. 多份简历管理

在现有工作区增加轻量简历入口，支持空白新建、复制、命名、搜索、归档、恢复和切换。每份简历独立持有内容、布局、来源上下文、草稿与版本图。首版用归档承接移出列表的需求，永久删除与回收策略后续单独设计。

新建可使用空白或已确认的导入内容。复制默认仅复制当前内容、布局和必要资源，建立新文档与独立初始版本；说明历史、助手会话和待审提议不自动复制。资源可按内容寻址共享，但归属和回收必须正确。

升级时将原默认简历原位纳入列表，保留 document ID、草稿、来源上下文、分支和提交身份，不用导出重导代替迁移。

宿主新增受控的当前文档选择。读取、保存、版本、导入、助手、fit 和导出绑定明确身份。切换前 flush；保存失败保留内容并阻止切换。切换后旧页面的保存和提议不得写入新文档。不能只删除 `DEFAULT_DOCUMENT_ID` 限制就认为安全完成。

已冻结的导出可以继续完成原简历文件，提示必须标明原目标。未确认导入或助手结果仍归属原目标，要求返回该目标或重新发起；未完成工作不得悄悄转移。

当前本机账户主要隔离助手状态，简历库仍沿用本地工作区语义，界面不暗示“切换账户即可隔离简历”。多人账户级文档隔离另需数据归属与迁移方案。

验收覆盖 A/B 同名简历、快速切换、编辑中切换、保存失败、旧响应迟到、导入/助手/导出中切换、复制后独立编辑、归档恢复、重启与全库备份恢复。每次只改变预期文档，其他正文、版本和资源保持正确。

## 6. 岗位定制

每份简历可保存岗位名称、公司、用户粘贴的职位描述、来源备注和更新时间。岗位描述作为本地材料，不默认抓取网页或接入招聘平台。

岗位版本复用现有分支：从用户选择的已保存状态创建岗位分支，关联岗位材料；主简历与其他岗位版本保持独立。材料修改保留修订，使建议能说明依据的职位描述版本。

助手先形成“岗位要求—已有事实—缺口—建议”的对应关系。已有事实指向用户显式选择的字段或经历；没有证据的要求标为缺失，不补造技能、经历、指标、证书或任职时间。

修改沿用提议链：选择范围 → 生成建议 → 展示原文、修改后与理由 → 逐项接受/拒绝 → 原子应用 → 符合条件时撤回。岗位材料和简历正文均为不可信输入，不能扩大工具权限或自动确认。

首版优先覆盖现有提议支持的基本字段、摘要和经历正文。自动新增/删除经历、调整模板或保存版本若超出现有命令，先提供建议，由用户用现有操作完成；新增自动动作必须先建立受限契约与副作用验收。

无模型服务时，本地检查和手动岗位版本仍可用。服务失败、取消、切换文档或材料过期均不影响已保存内容。保留 6 次模型调用、12 次工具调用和生产 90 秒预算。

验收：建议可追溯、无事实补造、只修改显式范围、旧材料触发过期提示、同名文档不串写、拒绝不改正文、撤回不覆盖后续人工编辑。

## 7. 投递前检查与导出

在已有导出入口提供轻量检查，复用溢出告警、冻结导出与原生保存。区分必须处理的错误和可忽略建议，不用一个不透明总分替代具体问题。

| 范围 | 首版检查 | 处理方式 |
| --- | --- | --- |
| 身份与修订 | 当前简历、岗位分支、未保存编辑、冻结版本 | 保存失败阻止导出，展示真实目标 |
| 内容完整性 | 占位文字、空模块、明显重复、关键联系方式缺失、未完成导入核对 | 定位字段，不自动补内容 |
| 日期与一致性 | 起止时间倒置、字段冲突、格式不一致 | 展示原因，不把合理并行经历判错 |
| 版面 | 溢出、缺字、异常空白页、过小字号、裁切 | 复用几何与字体诊断，不静默改版面 |
| PDF 可用性 | 文字可提取、主要阅读顺序、链接、页数、必要资源 | 检查实际冻结输出，而非仅屏幕预览 |
| 岗位相关性 | 岗位要求是否有事实支撑 | 解释对应证据和缺口，不承诺排名或录用率 |

“招聘系统可读性”只指可测的文本、结构和顺序，不宣称所有 ATS 解析一致，也不提供未经验证的万能通过率。

保留三套模板和当前正式 DOM 预览；默认切换至 SVG/引擎预览不属于本版动作。确需新模板时作为独立增量，验证中英文、长内容、头像、跨页、字体及 PDF/PNG 后再加入。

默认文件名可含简历名、岗位/分支和日期，允许修改。仅在真实落盘成功后记录文档、分支、提交或修订、模板版本、时间、格式和文件摘要；摘要只确认产物身份，不代替跨设备内容与视觉检查。

验收：问题可定位；忽略建议后仍可导出；保存/写盘失败明确；输出对应冻结修订；PDF 可检索、链接正确、PNG 页序完整，界面标记不进入文件。

## 8. 技术与数据边界

沿用既有分层：React 交互与缓冲，`src/platform` 类型化边界，Rust contracts/domain 结构与规则，storage 事务/版本/资源，engine 冻结排版，agent 上下文与提议，Tauri 权限与文件交付。

新类型由 Rust 定义，先定契约，再做核心、宿主和 UI，最后生成绑定。新增 IPC 同步 command union、handler、capability 和公共契约。当前 72 个 IPC 是基线，不是永远不能扩展的上限；有意扩展时四处保持一致。

优先复用文档、context、branch、commit、resource、proposal。最小新增信息包括文档展示元数据和归档状态、宿主当前文档、岗位材料及修订、岗位与分支关联、必要的导入校正信息和导出记录；具体 schema 在 M2 定稿，不向每张新表复制整份简历。

新对象绑定文档及必要来源/修订。资源引用覆盖待审导入、草稿、快照和导出租约；归档或删除一个对象不得回收其他文档正在使用的资源。

需要从 schema18 升级时，新增受控迁移并先验证备份。失败保留可恢复旧库；旧程序拒开未来 schema，回退使用兼容备份。全库备份 JSON 本身未加密，报告和测试不能公开真实内容。

保存、导入、提议、fit 和切换使用完整身份与修订校验。保留输入法缓冲规则，durable ack 后才表示已保存。列表、来源页面和历史快照按需载入，避免启动就加载全部文档与高清资源。

只针对实测瓶颈优化；同输入、机器、字体、工具链比较 p50/p95/max、峰值内存和取消释放。旧“五倍提速”目标不自动纳入本版，更不能减少检查覆盖来宣称达到。

结构、依赖或产品引用变化时同步相关 Archify、AST-grep、GitNexus 分析。索引仅作导航，UNKNOWN/空结果/跨语言缺边不是安全证据。未来修改前重新做 impact，本轮规划查询不代替未来编辑检查。

| 阶段 | 工作 | 交付与出口 | 粗估 |
| --- | --- | --- | --- |
| M0 导入基线 | 冻结样本和答案，测当前路径，分类失败 | 60份样本清单、支持矩阵、逐样本报告、修复优先级 | 3–5工作日 |
| M1 导入可靠性 | 修复复现问题，完善核对，完成保留组评测 | 四层识别验收通过，失败不污染，旧基准不退化 | 5–10工作日 |
| M2 文档与契约 | 文档元数据、activeDocument、岗位关联、迁移与隔离 | 契约、绑定与权限一致，迁移恢复和迟到写入验证 | 3–5工作日 |
| M3 简历工作区 | 新建/复制/命名/搜索/归档/切换，接入导入与版本 | 多份简历独立工作，切换、重启、恢复一致 | 5–8工作日 |
| M4 岗位定制 | 岗位材料、关联分支、事实对应、提议审阅 | 无模型可降级，无事实补造或跨目标应用 | 5–8工作日 |

| M6 发布候选 | 冻结输入、Windows功能链、升级恢复、资源许可 | 候选包、检查记录、升级说明、回退备份 | 3–5工作日 |

合计约 **27–46 个工作日**，外部样本收集与人工复核等待另计。识别复杂度是主要不确定性，不压缩数据安全验收来迎合估算。

独立样本标注、界面草图及不共享写入的审阅可以并行。契约、迁移、锁文件、索引和发布输入串行；原生/WebView2/bench/soak 和完整验证按项目约定独占执行。

阶段交接只更新 `plan.md` 的目标、已完成修改、验证结果、剩余问题和下一步，并链接证据。本文不维护第二份实时状态表。

工期紧张时先移出 P2、永久删除、批量导出和超出现有助手命令的自动动作；保留可靠导入、多文档隔离、岗位版本、基本检查和升级安全。M0/M1 可形成内部可用里程碑，其余主线完成前不标记整个 vNext 完成。
