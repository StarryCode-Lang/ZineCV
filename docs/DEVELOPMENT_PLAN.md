# ZineCV 开发设计与验证要求

本文件保留产品约束与实施方法。当前架构以[C+决策](ARCHITECTURE_TARGET_CPLUS.md)为准，实现状态见[SLICE](SLICE_20261002.md)，剩余任务见[plan](../plan.md)，历史只记入[HISTORY](HISTORY_202610.md)。旧版Svelte候选、desktop隔离目录和Agent启动提示词已退役；当前使用共享React、Rust Core和平台适配器。

## 1. 范围与完成定义

保留现有功能、UI/纸面布局、交互与用户数据。轻量化应减少重复实现、过时资料和可生成数据，不靠删功能、降低可读性或放宽验收。完整完成必须有功能矩阵、迁移恢复、UI/A4、性能、干净安装、许可与真实模型证据；缺外部条件如实记录。

文件和文档均可修改，无历史字节冻结。生成绑定长期变更优先来自Rust schema；历史记录不追改成当前通过。数据备份、隔离测试、权限、导出修订一致性及构建期间输入校验继续生效。提交、推送、发布按用户授权执行。

## 3. 文档、命令与持久化

保留全部基本字段、十种模块、summary及隐藏内容；稳定ID区分同名实体，sections为唯一顺序。富文本保留marks、嵌套列表、起始编号、换行、链接和中文空白；受控解析HTML，未知安全字段保留并报告，不将用户文本执行为Typst或脚本。日期按用户格式保存，年龄参考日期随渲染输入记录，布局逐字段换算单位，A4使用物理尺寸。

命令使用可信宿主会话、完整AuthorityCursor、CAS和事务幂等。相同commandId/请求重试返回原receipt，不同请求冲突；账户/context/较旧revision的迟到响应不能覆盖当前状态。只允许白名单字段和命令，不暴露任意SQL、文件路径、JSONPath或脚本。

UI串行发送同文档命令，普通输入可合并，composition结束后提交。保存状态只由durable ack确认；导出、提交、切分支和正常关闭先flush并等待持久结果，失败保留buffer并停止动作。强杀只承诺恢复已确认的编辑。富文本undo、Agent逆操作和版本恢复分别处理，避免跨文档撤销。

SQLite单writer、短事务、外键检查；WAL/busy重试与持久化策略由实际Store实现。canonical hash有格式版本，区分源字节与语义摘要；相同内容的不同历史提交仍保留身份与时间。正文快照不可变，可见提交关系可在删除事务中重接；默认分支和他分支祖先受保护，载入历史不移动head，替换版本库不自动替换草稿。

编辑context保存来源草稿，A→B→A及重启不得串改；同内容切内置版式只改presentation。GC保留草稿、快照、模板、待审导入及活动导出/备份的所有引用和lease，不只看已提交版本。头像仅保存草稿后GC/重启仍须可读。

## 4. 预览、资源与导出

保留三模板、density、overrides、主题、排版参数和未知版本提示。UI外壳与纸面分开验收；纸面同时检查截图、文本、页数和命中区域，不以新引擎为由接受显著差异。初始候选几何容差为外壳1 CSS px、纸面0.75pt，外壳像素差异率0.5%只作报警；具体测试沿用现行阈值，不扩大遮罩或放宽预算掩盖回归。

页码1-based、几何pt；UI按页面显示尺寸换算，DPR不重复乘到CSS坐标。跨页条目有多个fragment，点击优先具体entry，键盘按语义顺序，Esc恢复焦点；overlay不进入正文、SVG或导出。TextMap按UTF-16 shaping cluster表达连字、组合字符、双向文字与阅读顺序；文本层不参与排版，也不能被命中层阻断。

缓存身份覆盖文档、模板、字体、资产、引擎、布局、语言和参考日期。普通预览只保留活跃与最新待办，丢弃过期结果；超时或内存超限终止并重建worker，旧generation拒收。只在同worker/generation复用内部PagedDocument，重建后用同一输入重编译。资源只通过清单和受控只读通道提供，不允许任意路径/网络；缺失给出诊断，有界重试后保留旧页面并显示失败。

智能一页保持正文、顺序与语义hash，只枚举有界布局候选；每个候选实际排版，不假设页数单调，失败恢复原布局。候选数/超时以现行实现为准。PDF和PNG绑定调用开始时的修订与资源；PDF检查中英文提取、链接、阅读顺序、嵌入字体及A4，PNG保留默认纵向长图，超像素预算时明确处理，不能输出半文件。运行时资源身份不等于禁止更新资源文件。

## 5. 导入、迁移与恢复

PDF/DOCX/OCR适配器按需加载，产出候选、字段证据、原图、警告和不支持项，用户确认后事务写入。复杂DOCX的DOM预览留在受限环境，不硬搬进无DOM worker。扫描PDF先栅格化再OCR，低置信度待人工校正，不用模型补造内容；限制文件、页数、像素、ZIP解压、链接及超时，失败/取消不能改当前文档。原图覆盖与编辑后预览/导出语义明确区分。

旧浏览器origin的数据需显式导出/文件导入，不扫描整个profile。覆盖正文、布局、模块、来源context、模板活动、完整版本图、未提交草稿、设置、账户、provider和各账户会话；不迁移旧活动登录token，遗留运行标interrupted。真实简历、Key和.data不能进入公开测试或诊断。

流程为inspect→dryRun→审阅→commit→verify→receipt。源只读，提交时核对源身份和目标cursor；按source hash/importer version/namespace记录批次，按namespace/entity kind/legacy ID稳定映射实体。重复导入幂等，新增提交和升级importer不能整库翻倍；同ID不同内容显式冲突，同内容不同历史身份保留。损坏主文件与有效backup分别报告可恢复、丢失和待处理项。

在线备份使用一致快照，校验完整性、外键、资产与关系后发布；恢复先停写、flush、保留旧库并关闭连接，不混接旧WAL。升级前备份，未来schema拒写；应用回退先选择兼容DB副本，不能只换exe。用户旧数据和旧应用的处置另行授权。

## 6. Agent与身份

Bot/composer/chat及三工作区共享会话，导航不重建run。模型仅可只读或提出commands，确认通道在Rust侧检查账户、document/context/branch/head/revision、scope、before值、有效期和幂等；多条修改先完整校验，再一次事务应用。撤回检查预期after值，不能覆盖后续手改。

保留6次模型调用、12次工具调用、生产90秒预算及取消/迟到保护；断线保留已接收文本，不自动重放工具。只发送明确选择且脱敏的上下文；引用某对象不等于授权上传全库，文档内指令不扩大权限。connectionId由用户配置，Rust校验endpoint、重定向及DNS，SSE处理跨chunk UTF-8、结束/错误/取消；mock不证明真实模型通过。

匿名编辑不强制注册，本机账户按现有语义隔离Agent状态。旧scrypt兼容，密码和Key不明文持久化；Windows使用Current-user DPAPI，不用machine范围，不声称能抵御同OS用户恶意进程或加密整库。跨机恢复保留配置/密文并报告需重输，不默认删源秘密或将不可解密误记为连接不存在。

## 7. 可测量的性能与复杂度目标

以下均是**候选验收预算，不是已测结果或上游承诺**。记录基准机、release构建、Windows/WebView2版本、DPI与输入；以证据校准，不为通过放宽预算。

| 指标 | 初始预算/比较方法 |
| ------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 普通键入响应 | 主线程输入反馈 p95 ≤50ms；不得为等IPC阻塞IME |
| 1–2页普通编辑到新预览可见 | 热态端到端p95 ≤250ms，包含debounce/IPC/编译/绘制 |
| 5页复杂简历预览 | 热态p95 ≤750ms；持续输入仅最新修订生效 |
| 冷启动到可编辑 | 标准Win11+SSD release目标≤2s；引擎预热单独记录 |
| 模板切换 | 1–2页p95 ≤500ms；保留旧页面直到新结果可见但标明生成中 |
| PDF导出 | 5页目标≤2s；PNG另测DPI/长图内存，不用PDF预算混算 |
| 拖拽/折叠 | 60Hz设备p95帧时间目标≤16.7ms；无大于100ms输入卡顿 |
| 内存 | 记录主进程+WebView2子进程+worker总量；30分钟持续编辑后应平台化，任务结束回收；初始压力预算500MiB待基线校准 |
| 版本提交 | 1000个50KiB纯文本快照时p95 ≤150ms；头像/模板资源另计 |
| 自动化 | 共享构建一次，普通PR无重复全构建；报告耗时、flaky率与覆盖，不以删除断言提速 |
| 总维护量 | 2.0稳定实现手写生产代码目标比旧版等价范围减少≥20%，是优化目标而非删功能硬配额 |
| 结构复杂度 | 单一领域写入口；无循环依赖；每条校验规则单一权威；组件约400行/模块约800行作为review提示，非机械拆分命令 |
| 包体 | 分列应用本体、字体、OCR模型、WebView2离线包；不给“几MB”营销目标 |

采样每个场景至少30次，冷启动至少10次，报告p50/p95/max、失败次数和环境；重复3轮观察波动，不按最好一次报。旧版对照用独立profile和独立数据目录，绝不控制用户当前5173页面。这些候选指标不代表当前达标，实测范围见SLICE/HISTORY。

性能PoC应包含空白、1页、2页、5页、20/100/500条目、头像、混合列表、长链接和1000版本；超大输入另设产品上限，不能用极小样例证明所有规模。高耗时渲染与导入同时运行时仍能取消、编辑、关闭。所有性能改善需同功能、同字体和同内容对比。


## 8. 开发与交付

日常反馈与最小检查见[DEVELOPMENT_FEEDBACK](DEVELOPMENT_FEEDBACK.md)及AGENTS；阶段依赖见[C+执行计划](EXECUTION_PLAN_20261006-cplus.md)。不在每个小改后重复构建、full或长测。并行任务须路径和状态独立，公共schema/migration/锁文件、用户数据与同一profile不能共享并发写入。

接口变更先检查调用影响，同步Rust、handler、capability、公共契约和生成绑定。清理旧实现前核入口、引用和测试，不根据空调用图判无用。功能、迁移、进程/权限、原生IME/文件、安装离线、真实模型、视觉、性能、许可和第二执行者复现分别验收，不把build或局部通过升级整体完成。授权与开发完成分别记录。

出现数据丢失、越权写入、错误保存提示、不完整导出、生产测试入口、未获授权的再分发或性能宣称无证据时，停止受影响动作并保存诊断。文档可改、基线可审查更新；不能靠改基线掩盖回归。
