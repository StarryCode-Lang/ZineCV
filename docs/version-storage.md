# 版本存储与恢复

## 运行位置

本地使用 `npm run dev`，或构建后使用 `npm run preview`，固定打开 `http://127.0.0.1:5173`。端口被占用时会直接报错，不会自动换地址。只有开发/预览服务启用了项目文件接口后，已提交版本才会写入项目目录；普通静态托管只能提供浏览器缓存。

## 两层存储

### 浏览器层

浏览器保存草稿、排版偏好、模块顺序、模板识别结果和未提交版本。常用键包括：

- `resume-diy-state`：简历正文和个人信息。
- `resume-diy-preferences`：字体、间距、主题和智能一页状态。
- `resume-diy-presentation-v1`：当前格式、模板版本和排版覆盖值。
- `resume-diy-imported-templates-v1`：导入模板的识别结果和压缩缩略图。
- `resume-diy-section-order-v2`：模块顺序。
- `resume-diy-version-store-v1`：版本提交图和分支历史缓存。

浏览器已有存档时，默认数据不会覆盖当前内容。全新浏览器没有草稿时，会在可用的项目文件服务中恢复当前分支已提交快照。

### 项目文件层

版本提交、分支创建、切换和删除保存到：

```text
.data/
├─ versions.json          当前项目版本库
└─ versions.backup.json   上一次成功写入的完整备份
```

`server/version-storage.mjs` 负责文件读写，写入采用临时文件和原子替换；`src/services/version-storage.ts` 负责请求、迁移合并和缓存；`src/app/useResumeVersions.ts` 负责提交流程。`.data` 是用户数据，已被 Git 忽略，不能为了测试、构建或发布而删除、清空、恢复或提交。

## 启动与迁移

首次连接项目文件服务时，会合并当前浏览器中尚未迁移的旧提交；已同步的浏览器重新打开时以项目文件为准。模板和版本记录仍按各自的当前上下文保存，切换模板不会把其他模板的编辑状态覆盖掉。

普通静态托管没有文件接口，界面会明确显示“已保存到当前浏览器”，不能把它描述为项目文件保存成功。

## 冲突与损坏保护

- 多窗口同时修改时，旧窗口不能覆盖新窗口已经保存的版本，会提示刷新。
- 项目文件读取失败、JSON 损坏或 schema 不匹配时，暂停版本操作并保留原文件，不能把错误解释成空版本库。
- 删除版本会重接父子提交和分支头，删除当前分支前会保留当前工作分支的可达历史。
- 备份和恢复测试使用独立数据目录，不触碰用户 `.data` 或正在使用的 5173 页面。

## 版本界面

“版本历史”显示全部提交的独立列表；“选择分支可视化”按父提交关系显示分支树。节点可以选中并恢复，分支树支持键盘操作、横向拖动和以指针为中心的缩放。视图和状态均来自同一份提交图，避免历史列表与分支树失步。

## 验证

```bash
npm run test:versions
```

该命令覆盖 schema、跨服务重启、换端口、全新浏览器恢复、冲突保护、备份和损坏文件保护。测试数据只写入被忽略的临时目录；真实用户版本文件应保持原样。
